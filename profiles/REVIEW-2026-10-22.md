# Six project profile drafts: owner review guide

Date: 2026-10-22

This document explains six *provisional* selections explicitly authorized for browsing and revision. The six profile ideas were instantiated as `PROFILE-0003` through `PROFILE-0008`. Each has `status: draft`, `review.selection_confirmed: false` and `review.finalization_confirmed: false`. These flags deliberately do **not** misrepresent the user's permission to create a draft as approval of its individual rule choices. The original `PROFILE-0001` and `PROFILE-0002` C-to-Rust drafts and their confirmed selections are unchanged.

## Browse the actual selections

Open [the Nomos catalog](https://sguzman.github.io/nomos/), set **Item type → Profiles only**, find a named draft, and use **Browse members** to inspect each published rule in the selected list. The profile files in this directory contain the canonical selected IDs and nothing is applied by browsing. A draft cannot be bulk-activated or finalized without later explicit approvals.

Each Lite selection is a **strict subset** of its corresponding Full selection; every ID points to an existing published atomic rule.

### Rust project from scratch

**Lite** selects general public-repository/privacy protections, Git branch and change-scope practices, Rust/Cargo edition and toolchain checks, formatting, Clippy, build checks, core unit/integration/regression testing, limited documentation, and evidence-based acceptance/completion reports.

**Full** adds deterministic and feature-matrix testing, CI and deployment checks, richer documentation, progress bars and roadmap reporting, versioning, releases, and the documented MVP/post-MVP lifecycle. It does not select the strict software-port/C-to-Rust-specific behavioral-parity rules `NOM-0074..0076` and `NOM-0111..0113`.

### Independent Tarium project

**Lite** selects both earlier Tarium ontology/showcase requirements (`NOM-0006/0007`) and the eight foundation-specific rules (`NOM-0115..0122`), plus independently usable repository, public privacy, licensing, provenance, and verification guidance.

**Full** adds all six advanced Tarium-specific atoms (`NOM-0123..0128`), including controlled externalization, publication review, enrollment *preflight only when explicitly authorized*, evolving ontology semantics, gallery-index integrity, and accurate membership claims. It also adds generally applicable documentation, CI, release, project identity and progress rules. It does **not** assume every Tarium project is written in Rust, an executable software application, or already an enrolled Tarium member.

### Rust fork maintenance

**Lite** selects public-repository protections, branch and history checks, Cargo/Rust validation, compatibility checks, key tests, minimal documentation, and verifiable reporting suitable for scoped upstream-derived maintenance.

**Full** adds comprehensive validation, CI, deployment, documentation, versioning, progress reporting, and later maintenance/release practices. It does **not** inherit strict C-to-Rust parity/port-MVP rules merely because a repository is a fork.

**Newly available optional rules:** `NOM-0129`–`NOM-0134` now publish the upstream baseline, divergence, patch provenance, reconciliation, post-integration verification and selective adoption requirements. They were processed independently of these profiles; the fork Lite/Full selected member lists remain exactly as drafted and unconfirmed until the owner reviews them.

## Review and approval boundaries

- An explicit **draft-instantiation** request permits storing proposed profile records, not treating their content as selected or approved for use.
- `review.selection_confirmed=false` on these six profiles must remain false until the owner accepts the selected IDs.
- A rule being in a profile never overrides its own scope or permissions; related rules may overlap and reviewed relationships do not automatically grant precedence.
- Full adds greater coverage than Lite, not arbitrary authority to start new repositories, change Tarium membership, publish private work, or inaugurate projects without their separate approvals.
- A later **selection confirmation** and later **finalization** are distinct steps. Even finalized profiles do not auto-export or install instructions.
- No profiles added here require private Taria source materials or copy private conversation text into this public repository.
