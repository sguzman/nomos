# Disposable Luna/Codex acceptance runner

**State: implemented and mechanically tested; no live Luna run accepted.** This utility is for isolated behavioral evaluation, not for normal application development or activation of the draft Rust profile.

## Cases and isolation

The runner `tools/run_luna_acceptance.cjs` prepares three public-safe Rust exercises aligned with the agent-consumption acceptance matrix: `RUST-CLI` for normalizing command-line input, `RUST-PERSIST` for durable journal state, and `RUST-MIXED` for overlapping Tarium/Rust project facets and untrusted input. They deliberately use a *synthetic, disposable, ad-hoc selection* of the 106 published source rules referenced by the **unconfirmed** Rust Full draft. No actual profile is finalized, selected for a real project, or published.

For all three scenarios without repeated manual setup, `node tools/run_luna_acceptance_suite.cjs` previews them together. `node tools/run_luna_acceptance_suite.cjs --model MODEL --execute` explicitly invokes an already authenticated Codex CLI for the three isolated scenarios; it still leaves independent acceptance pending, even if all Cargo tests succeed.

The default command is a harmless planning preflight:

`node tools/run_luna_acceptance.cjs --case RUST-CLI`

It computes the pinned projection/package and prints a public-safe plan. It does not call Codex, Cargo, Git, an external API, or any live project. CI tests this planning behavior without agent authentication.

## No-model sandbox permission check

On Linux, first run `node tools/run_luna_acceptance.cjs --case RUST-CLI --probe-sandbox`. This executes Codex's own **sandbox helper only**, not a coding agent or paid model. It creates a temporary Git directory, tests writing and removing a file inside `.git` under the proposed limited profile, then deletes the disposable directory. A successful check is only evidence that the current local sandbox permits Git writes; it does not imply any Codex behavioral compliance. A failed check does not launch an agent and must not be overridden with unrestricted sandbox flags.

Actual unattended execution is **separately opt-in**, with an already installed and authenticated Codex CLI. First the runner checks the local CLI parser with the restricted Git-write profile and `exec --help`. After creating its disposable baseline but **before any model invocation**, it calls `codex sandbox linux --permission-profile nomos_disposable_git` with the same scoped configuration to create and remove one temporary `.git` probe file. A failed permission probe stops before contacting a model. This test runs on Linux; it neither pushes commits nor touches a real repository. No automatic escalation to unrestricted access is permitted.

`node tools/run_luna_acceptance.cjs --case RUST-CLI --model MODEL --execute`

The model flag is optional and must be chosen from those available in the authenticated account; the runner does not invent model availability. It uses `codex --ask-for-approval never -c ... exec --ephemeral --json --cd <temp-repo> -`; the prompt is sent on stdin. This ordering supports Codex CLI 0.163.0, where placing the approval flag after `exec` fails parsing. **The per-invocation `-c` overrides define a disposable-only permission profile extending `:workspace` and explicitly allow `.git` writes inside the Codex workspace**, so Git staging and commits can operate in the temporary repository. For the filesystem override, the runner passes the **single TOML inline map** `permissions.nomos_disposable_git.filesystem={":workspace_roots"={".git"="write"}}`: passing `filesystem.":workspace_roots"=...` as separate CLI dotted keys mistakenly treats the quoted special path as a literal filename and fails configuration parsing. Successful real Git writes remain unverified until the local no-model probe passes. No persistent Codex or Git settings are modified, and command networking stays disabled. This does **not** grant full filesystem access; the runner never uses `--yolo` or `danger-full-access`.

When explicitly executed, it creates a new temporary Git repository and Cargo project under OS-managed temporary directories, configures a synthetic Git identity **only in that temporary repository**, installs a separate synthetic test package there, and invokes Codex only against that test directory. It also removes any inherited `RUSTC_WRAPPER` (notably `sccache`) **from the disposable Codex/Cargo subprocesses only**, avoiding known sandbox-incompatible wrapper launches without changing the user's environment. It then runs `cargo test --offline`, `cargo fmt --all -- --check`, `cargo clippy --offline --all-targets -- -D warnings`, and `cargo metadata --offline`, queries Git status and history, and saves raw JSONL tool events and stderr to a separate private temporary evidence directory with restricted permissions. It never points at an actual user project, uploads raw logs, approves a real profile, or pushes commits to a remote.

## Disposable pre-commit artifact gate

For **explicitly invoked disposable** Rust acceptance runs only, the runner installs a Git pre-commit check scoped to the temporary test repository, *after* the synthetic baseline commit. This check derives its conditions from the pinned synthetic projection and selected source-rule IDs. Under the from-scratch condition, it checks for a staged README (`NOM-0042`) and roadmap (`NOM-0010`), accepting documented conventional paths. The roadmap also receives a **conservative structural preflight** for explicit phase/milestone/feature/subtask entries and unique per-item identifying emojis distinct from status symbols. A missing file or structurally incomplete roadmap rejects the commit and identifies the source-rule issue; Codex must correct the authorized project artifact and retry normally. A successful commit proves only that this limited staged-artifact preflight passed; it is **not** semantic source-rule acceptance. The runner independently rechecks the roadmap structure after the model turn and reports `roadmap_structure_incomplete` in `independent_review_gaps` when applicable, even if the agent bypassed the Git hook. Full conformance remains subject to independent trace and repository review.

The hook does **not** get installed in user projects, global Git configuration, or normal Nomos package exports; only the opt-in synthetic test creates it. It does not edit a missing roadmap, trigger another model attempt automatically, or grant permission to process any queued task. This is a targeted regression guard for repeated observed omissions, not a general solution to agent-rule compliance.

## Conditional handoff-progress preflight

The independent Rust review also found that an otherwise fully working implementation can omit **selected reporting obligations**. The disposable test prompt therefore requires reviewing `NOM-0068` through `NOM-0072` before the final agent message: progress for touched roadmap phases and items; an overall project summary; and percentages with matching visual bars only where evidence supports quantification. First-time 100% notices are reported once, without manufacturing percentages for unknown work. The committed roadmap must also remain truthful after the final Git action: an in-progress milestone is disclosed as incomplete or reconciled in a verified follow-up commit where appropriate.

The runner separately examines the final completed Codex agent message and reports a bounded `handoff_progress_preflight` recording whether an overall progress cue, numerical percentage and visual bar were observed. When selected rules apply and a final message is available but those signals are absent, the runner lists the corresponding `handoff_missing_* ` gaps and refuses to present the run as ready for independent review. This is only a **presentation-shape signal**: it cannot validate denominator accuracy, rule applicability, item coverage, semantic correctness or a genuine first-time completion event. Missing raw final-message evidence remains unobserved, never silently successful. Independent rule-by-rule review remains mandatory.

## Observable evidence

`tools/codex_trace_observer.cjs` parses Codex's `item.completed` command-execution JSONL events and identifies successful `node .nomos/read-phase.cjs <phase>` commands with matching `NOMOS_PHASE_READ` receipts. It validates those receipts against the package's pinned manifest and records actual command statuses. It does **not** treat an agent's natural-language claim as a tool event and it never marks applicable rules `satisfied` automatically.

The report distinguishes `invocation_attempted`, `session_started` (a JSONL `thread.started` event), and `agent_turn_completed` (a genuine `turn.completed` event plus zero CLI exit and no `turn.failed`). A parser exit with no session event is `launch_failed`. A completed turn **without** a fresh post-baseline Git commit, a clean worktree, and a successful post-run Cargo test is `agent_workflow_incomplete`, not `awaiting_independent_review`; those mechanical facts are separately reported as `agent_created_commit_count`, `worktree_clean`, and `code_test_commit_gate_met`. A qualifying mechanical run still requires independent rule-by-rule assessment. The runner also saves the full agent-created Git patch relative to its synthetic baseline plus test/format/Clippy stdout and stderr. After `--execute`, it attempts to create a **private** `nomos-<case>-<unique>-review.tar.gz` in the invoking user's `~/Downloads` directory (falling back to the private evidence directory if Downloads is absent) and prints its exact `private_review_bundle` path and `private_review_bundle_sha256` in the returned JSON. The archive combines the disposable project source with named evidence files, including the raw tool events, while excluding `.git` internals and `target` build output. Nothing is uploaded or committed. **Inspect the archive before sharing it with any reviewer**: raw traces may contain machine paths or unexpected sensitive text; never commit an archive or raw trace to this public repository. The report also captures **offline Cargo formatting and Clippy check exit statuses** and repository-artifact presence for README, project roadmap and GitHub Actions workflows. Missing files or unsuccessful tools appear in `independent_review_gaps`; they do **not** silently alter the limited `code_test_commit_gate_met` predicate or claim a rule violation without applicability review. `RUST-CLI` explicitly requires a CI workflow to align with `EVAL-08`; the workflow is inspected locally, not falsely claimed to have run on GitHub. Cargo success on the untouched synthetic baseline is not agent work. `production_accepted: false` and `independent_reviewer_accepted: false` remain fixed. A separate reviewer must inspect actual agent-created commits and changes separately from the baseline, original tool traces, phase transitions, applicable conditions, builds, tests and any missing work. The existing conformance rubric requires three independent, distinct, accepted real-agent runs before a scoped production claim.

Minimal RUST-CLI rerun: `node tools/run_luna_acceptance.cjs --case RUST-CLI --execute`. Keep the generated evidence directory private. A run without `thread.started` is a launch failure. A run with successful code/tests/commit but missing required repository artifacts is now explicitly classified `requires_artifact_remediation`, while a mechanically complete run with no identified artifact omissions is `awaiting_independent_review`. Neither status is production acceptance.

The first mechanically complete Rust CLI run passed the Cargo/commit/clean-worktree gate but a limited independent review found the absence of a README and new-project roadmap, and could not establish formatting and linting checks. The next Rust CLI run had a README, CI configuration, passing formatting and Clippy, and an actual Git patch/trace, but still omitted the mandatory new-project roadmap despite loading its rule. **Both remain unaccepted.** Review details are recorded in `agent-consumption-release-status.md` without publishing the raw Codex transcript.

## Known limitations

- No existing Codex/Luna installation or authentication has been accessed by this repository's CI. Tests only exercise inert scenario planning and synthetic trace parsing.
- The runner records command-event evidence but does not independently authenticate the model or determine whether an observed command reflects useful reasoning. Tool output can contain private content; raw logs stay in private local temporary storage and must never be checked into the public repository.
- The first two observed Codex 0.163.0 trials showed six passing Rust tests and five phase-reader receipts each, but failed the Git commit gate because default `workspace-write` protects `.git/index.lock` as read-only. The temporary-Git permission override passed a separate model-free local test with the user's Codex CLI 0.163.0. The later Rust CLI Codex run also created its own commit. This establishes local disposable Git writability on that tested version only; it does not establish compliance with the selected rules or compatibility with later Codex releases. Parser preflight alone cannot prove the filesystem policy works.
- A 15-minute model-run limit, custom workspace-based permission profile, and offline Cargo testing may expose target-specific failures. Those must be recorded, not waived to make a scenario pass.
- A GUI-specific end-to-end case and external target-environment verification remain separate future validation work; `RUST-PERSIST` covers the non-GUI alternate case only.
- This is an opt-in test tool, not a permanent service or background automation. It will not start unrequested paid inference.
