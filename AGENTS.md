# Nomos agent guidance

Read [CONSTITUTION.md](CONSTITUTION.md) before working on this repository. This file concerns **contributing to Nomos**; it is not a general-purpose agent template generated by Nomos.

## Mission

Build a small, extensible rule registry with rich metadata supporting scoped comparison and eventual ruleset composition/export. A catalog record is inert until explicitly selected for a consumer.

## Operational constraints

- **Public-content boundary:** Never insert private conversations, personal venting, secrets, private linguistic examples, unpublished user material, or close paraphrases into files, issues, commits, fixtures, or website output. Use synthetic, neutral examples only.
- **Scope:** Implement what was assigned. Do not treat a queue entry, roadmap line, specimen, proposed rule selection, or speculative use case as permission to execute it or instantiate a profile.
- **Branches:** Work directly on the existing `main` branch unless explicitly instructed otherwise for this task. Preserve unrelated files.
- **Model:** Preserve five distinct kinds: independent rules, categories, predefined virtual groups, **optional user-approved rule-profile presets**, and **explicitly invoked situational prompts**. Prompts are not rules, profile selections, or instructions to the contributing agent. Do not persist transient use-case discussion or AI rule suggestions as a profile without explicit authorization.
- **Conflicts:** Analyze shared normalized action/object/target and overlapping applicability facets; report candidates and uncertainty. Do not silently resolve by numeric authority.
- **Independence:** Do not add this repository to Tarium or other registries without explicit authorization.
- **Evidence:** Report which files changed, commit ID if available, validation/tests performed, and remaining work. Never claim work or QA not actually performed.

## Four distinct workflow surfaces

| Surface | Meaning | Not equivalent to |
| --- | --- | --- |
| `queues/specimens/` | Proposed specimens | Permission to process specimens |
| `processing/specimens/` | Authorized specimen analysis | A development task queue |
| `queues/tasks/` | Proposed or queued work | Permission to execute tasks |
| `processing/tasks/` | Authorized work in progress | A specimen analysis queue |

See [WORKFLOW.md](WORKFLOW.md). Keep status transitions explicit and attributable. A finished specimen analysis may propose a task but must not automatically enqueue or execute it.

## Local checks

```sh
python3 tools/validate.py
python3 -m unittest discover -s tests -v
```

The validator is intentionally limited. Inspect the changed Markdown/JSON and scrub public output for privacy risks before committing. Do not infer that a passing test proves semantic correctness.

## Profile presets are inert

Profiles are optional selections, not mandatory instructions. First discuss the use case and suggest existing catalog rule IDs *without persisting a profile*. Await explicit authorization before instantiating a draft. Allow add/remove in the draft and require separate approval to finalize; another explicit choice is required to select or export the finalized preset. Never create a default profile or activate one on a user's behalf. See [PROFILE_WORKFLOW.md](PROFILE_WORKFLOW.md).

## Situational-prompt intake is not publication

`queues/situational-prompts/` holds independent `SIT-IDEA-*` metadata proposals, not `SIT-*` registry entries. Preserve the scenario labels and applicability metadata, but do not copy owner-supplied chat text, private wording, or launcher keybindings into public JSON, code, issues, fixtures, or the website. Queueing is never approval to publish or activate a prompt. See [queues/situational-prompts/README.md](queues/situational-prompts/README.md).

## Situational prompt revision queue

The revisions directory under queues/situational-prompts/ holds independently versioned proposals for existing canonical SIT IDs. Preserve exact source-text checksums and predecessor links; do not copy local launcher keys or user-assigned labels into the metadata. Never auto-process, publish, select, or activate these proposed revisions. Pay special attention to reminders becoming execution instructions. See [queued revisions](queues/situational-prompts/revisions/README.md).

## Profile-idea queue is intake, never processing

`queues/profiles/` stores **ideas** with independent `PROFILE-IDEA-*` IDs. Creating a queue entry does not grant permission to investigate it, choose rules, instantiate a `PROFILE-*` draft, finalize, or export. The separate `profiles/` registry remains the only place for authorized profile records. No queue entry should be silently promoted, and no private wording belongs in the public queue. See [queues/profiles/README.md](queues/profiles/README.md).
